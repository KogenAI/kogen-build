# Cover the last-20 facts history limit

Slug: facts-history-cap-regression
Model: not applicable — only regression tests of an existing, unchanged facts rule are added; no state or rule changes
Acceptance:
- .kogen/intents/facts-history-cap-regression/acceptance.feature
- features/steps/facts-history-cap-regression__steps.js
- features/steps/facts-history-cap-regression__control.js

This Intent adds regression tests to `build/facts_test.go` that pin the last-20 history contract of the local facts record in `build/facts.go`: inheriting a previous run's facts keeps the newest 20 verification entries and, independently, the newest 20 review entries, in their original order; recording a 21st evidence entry keeps the newest 20 and sets `evidence_truncated` to true. Only `build/facts_test.go` changes. The facts formats, the summary fields and the history limit of 20 stay as they are, and `build/facts.go` is not edited.

## Decisions
- Add three new test functions and their small helpers to `build/facts_test.go`, leaving the existing tests unchanged: one inherits a previous facts file holding 25 verification entries and checks that the newest 20 remain in order; one checks, from the same file holding 27 review entries, that the newest 20 reviews remain in order, so a limit shared by the two lists is rejected; one records 21 evidence entries through `evidence` and checks that after the 21st the newest 20 remain in order and `evidence_truncated` is true, while after the 20th it was still false. (constraint: only build/facts_test.go changes; build/facts.go, the facts formats, summary fields and the limit of 20 stay unchanged) (evidence: build/facts.go; build/facts_test.go) (source: request)
- Acceptance cannot name tests the Build writes, so it runs every `Test` function that `build/facts_test.go` declares against the unchanged `build/facts.go` (all must pass) and against eight in-memory copies of `build/facts.go`, each with one defective limit (oldest 20 kept or no limit, for the verification list, for the review list and for evidence; one limit shared by verification and reviews; entries dropped without setting `evidence_truncated`), each of which the tests must reject. (constraint: the copies are used through go test -overlay and no checkout file is changed) (evidence: build/facts.go; build/facts_test.go; features/steps/b-consumes-tools-require-executable__steps.js) (assumption: the Go toolchain in the acceptance environment supports go test -overlay, which a read-only probe of the Go toolchain here did) (source: request)
- Add three new tests and helpers to build/facts_test.go: inherit keeps the newest 20 of 25 verification entries in order; inherit keeps the newest 20 of 27 review entries in order independently of the verification list; the 21st evidence entry keeps the newest 20 and sets evidence_truncated (false at 20). (decision: D1, round 1) (constraint: only build/facts_test.go changes; limit of 20, formats and summary fields unchanged) (evidence: build/facts.go; build/facts_test.go) (source: request)
- Acceptance runs every Test function of build/facts_test.go against the unchanged build/facts.go and against eight overlay copies of facts.go with one defective limit each, requiring rejection. (decision: D2, round 1) (evidence: build/facts.go; build/facts_test.go; features/steps/b-consumes-tools-require-executable__steps.js) (assumption: go test -overlay availability in the acceptance environment was observed only by a local read-only probe.) (source: request)
- The scope scenario does not rely on a dirty working tree, because verification runs acceptance in a clean candidate checkout where `git status --porcelain` is empty. Its step always requires `build/facts.go` to still contain the last-20 limit code the defective copies replace and, only when git status lists changed files (the builder's checkout), requires the files besides the Intent and its acceptance steps to be exactly `build/facts_test.go`. In a clean candidate checkout the scope of the change is left to the independent review against this Intent. (decision: correction of Build 1c35fdf0) (constraint: the original scope, only build/facts_test.go changes, is unchanged) (evidence: features/steps/facts-history-cap-regression__steps.js; features/steps/facts-history-cap-regression__control.js) (source: request)

## Tests
- Inherit keeps the newest 20 verification entries in order: new test in `build/facts_test.go` over a 25-entry previous facts file; acceptance runs it against the unchanged and the defective copies of `build/facts.go` (regression)
- Inherit keeps the newest 20 review entries in order, independently of verification: new test in `build/facts_test.go` over a 27-entry review list beside 25 verification entries (regression)
- A 21st evidence entry keeps the newest 20 and sets evidence_truncated, which is false at 20 entries: new test in `build/facts_test.go` calling `evidence` 21 times (regression)
- The facts rule stays unchanged and only the facts tests change: acceptance scenario 4 checks that `build/facts.go` still holds the limit code and, where git status lists changes, that `build/facts_test.go` is the only changed file (regression)
