# Stop reading the commit message file after Commit

Slug: b-commit-message-file-removed-after-commit
Model: not applicable — one consumer test stops reading a file after a call returns; kogen-build gains no state or rules
Acceptance:
- .kogen/intents/b-commit-message-file-removed-after-commit/acceptance.feature
- features/steps/b-commit-message-file-removed-after-commit__steps.js
- features/steps/b-commit-message-file-removed-after-commit__control.js

kogen-coordinator's pending change coord-commit-message-file-private (candidate 28df1f77, Build 055b5417) makes `(*git.Repo).Commit` create the commit message file at `git.CommitSpec.MessageFile` exclusively with mode 0600, refuse a symlink or other non-regular file at that path, replace a regular leftover file, and remove the file after the commit, whether the commit succeeded, failed or was interrupted. kogen-coordinator's current main, and the version `go.mod` pins (`v0.0.0-20261105001101-4116df40cbf1`), write it with `os.WriteFile(..., 0o644)` and leave it behind. With the candidate, the land's consumer contract check fails in kogen-build:

`TestCommitLandsTheReviewedTree  git_commit_test.go:62: open commit-message.txt: no such file or directory`

After this change kogen-build no longer depends on the message file after `Commit` returns, so kogen-build lands in either order with the coordinator change: its suite passes with the coordinator that leaves the file behind and with one that removes it.

What holds now (inspected at HEAD 891d430):
- `consumes/kogen-coordinator/git_commit_test.go`, `TestCommitLandsTheReviewedTree`, line 62: `equal(t, "git.CommitSpec.MessageFile: the message file", readFile(t, spec.MessageFile), "Add the app\n\nKogen-Intent: add-app\n")` reads the file after `repo.Commit` returned. This is the only read of the file after `Commit` in kogen-build. The same test already checks the committed message from the commit at line 61: `equal(t, "git.CommitSpec.Title and Slug: the commit message", f.log(t, "%B"), "Add the app\n\nKogen-Intent: add-app\n\n")`, where `f.log` runs `git log -1 --format=%B`.
- `TestCommitFailureLeavesHeadAndTheIndexRestorable` and `TestCommitUndoesACommitAHookChanged` set `MessageFile: filepath.Join(t.TempDir(), "commit-message.txt")` but never read it; they pass with either coordinator (probed).
- Non-test code: `build/commit.go` passes `MessageFile: filepath.Join(b.Run.Dir, "commit-message.txt")` to `Commit` and never reads it; nothing else in `build/`, `cmd/` or `contract/` names the file, and the commit message the Build needs before committing goes through `(*git.Repo).CheckCommitMsg(s, title, slug)`, not through the file. `build/legacy_test.go` and `build/legacy76_test.go` write their own `commit-message.txt` for a plain `git commit -F` of a fixture, not through `Commit`, and are unaffected. So there is no non-test code to change; the Build keeps it as it is.

Required end state:
1. `TestCommitLandsTheReviewedTree` no longer reads `spec.MessageFile` after `repo.Commit` returns: the `readFile(t, spec.MessageFile)` assertion is removed. The committed message stays checked from the commit (`git log -1 --format=%B`, the existing `f.log(t, "%B")` check, expected `"Add the app\n\nKogen-Intent: add-app\n\n"`). Its compile-time use `var _ string = spec.MessageFile` and its `MessageFile: filepath.Join(t.TempDir(), "commit-message.txt")` stay, so the test still names `git.CommitSpec.MessageFile` and the inventory row of `consumes/README.md` stays true. The comment above the test no longer says the test relies on the file's content after the commit; it may say that the message file is the run's commit-message.txt, where Commit writes the message for `git commit -F`.
2. No test in kogen-build reads, stats or otherwise requires `git.CommitSpec.MessageFile` (or a Build's `<run dir>/commit-message.txt`) after `Commit` returns, nor requires it to be absent. `TestCommitFailureLeavesHeadAndTheIndexRestorable` and `TestCommitUndoesACommitAHookChanged` keep naming `git.CommitSpec.MessageFile` and keep every assertion.
3. Unchanged: `go.mod` and `go.sum` (the coordinator pin stays), every non-test file, every other assertion, every golden, and every timeout (no `-timeout`, no alarm change). No test is skipped.
4. Report. The Build's finish summary reports one run of the full suite, `GOFLAGS=-trimpath go test ./...`, against a coordinator that removes the message file: a temporary copy of the pinned kogen-coordinator module (outside the checkout) whose `git/commit.go` gets `defer os.Remove(spec.MessageFile)` right after the message file is written, used through a temporary copy of `go.mod` (plus `go.sum`) with `replace github.com/KogenAI/kogen-coordinator => <copy>` passed as `-modfile`. The report gives the command and each package's result. No checkout file or Git state changes for it. (The full suite takes several minutes, beyond the acceptance run's limit, so acceptance runs the commit tests and the report covers the whole suite; the configured go-test check covers the pinned coordinator.)

## Decisions
- kogen-build no longer depends on the message file after `Commit` returns; a test that checks the message reads it from the commit with `git log -1 --format=%B`. (source: request)
- Non-test code keeps no copy of the message because none of it re-reads the file; the Build changes no non-test code. (source: request)
- The suite passes both with kogen-coordinator's current main / the pinned version (the file is left behind) and with a coordinator that removes the file after the commit, as candidate 28df1f77 does, with no test skipped and no timeout raised. (source: request)
