# Cut per-Build fixed costs in the build tests

Slug: k-go-suite-profile
Model: not applicable — only the build package's test fixtures, its test PATH and t.Parallel calls change; kogen-build's product code, state and rules do not
Acceptance:
- .kogen/intents/k-go-suite-profile/acceptance.feature
- features/steps/k-go-suite-profile__steps.js
- features/steps/k-go-suite-profile__control.js
- features/steps/k-go-suite-profile__shared.js

Almost every test of `./build` runs one or more simulated Builds (a real `Build` against a scripted provider), and the package's wall time is the sum of those Builds over go test's parallel slots. Profiling shows that most of each Build's fixed cost is not the Build's own work but the tests' environment: every verification pass starts each toolchain on the host's PATH to record its version, and every fixture project writes a new acceptance script whose first run waits for macOS's check of a new executable. After this change the package's tests give their Builds a PATH of only the tools the tests use, every fixture project runs one shared, read-only acceptance script, and the five slow tests that ran one at a time run in parallel. Every assertion stays. Only `_test.go` files under `build/` change.

What holds at HEAD a9edb84 (measured on 5 Nov 2026 on the request's MacBook: Mac16,8, 12 cores, macOS 26.7.2, go 1.27.2, `GOMAXPROCS=4` in the environment, so go test runs `-parallel 4`):
- Whole package: `GOFLAGS=-trimpath go test -count=1 -json -timeout 285s ./build` (load average 4.5 rising to 7.7) was stopped by that probe's 285 s alarm with 306 of 338 top-level tests finished. The 579 finished leaf tests sum to 1031 s. Its first 32.4 s ran the 27 non-parallel tests one at a time, three of four slots idle: `TestWholeIntentRedFeedbackEndsWithTheFinishReminder` 9.0 s, `TestStandaloneBuildEvidence` 6.0 s, `TestSuccessiveModelIntentsKeepIndependentSpecifications` 3.7 s, `TestUnmovedScopedFeedback` 3.5 s, `TestUnmovedExternalFeedback` 3.4 s, `TestResumeVerifiesMaintainedModel` 2.3 s, `TestBriefCapsReachNativeBuild` 2.0 s, `TestModelFreeBuildDoesNotCreateModelStorage` 1.9 s, the other 19 under 1 s. The largest leaf sums were `TestOneInvalidVerdictIsSentBackAndASecondEndsTheBuild` 71.7 s (24 leaves), `TestRecoveryRefusals` 47.7 s (16), `TestAResumeStillRefusesEveryChangeToWhatIsStaged` 32.9 s (11), `TestKReviewVerdictStrandSafety` 29.6 s (6) and `TestClaudeLineupReviewRoundLimit` 27.9 s (4): many Builds each, no single slow wait.
- One reviewed Build with one verification pass, run alone: 2.2 to 2.6 s wall and 2.45 CPU-s (user 1.01, sys 1.44, children included), 136 git processes. By kind:
  - Process start, toolchain versions: kogen-verification's check identity runs `<tool> --version` (`go version`) for go, node, npm, ruby, bundle, python3, elixir, erl, mix, git and quint wherever the session's PATH finds them, once per verification pass. The tests' sessions inherit the host PATH, so on this host that is about 0.9 s wall (mix 226 ms, elixir 163, erl 128, bundle 120, npm 93, ruby 47, python3 43, go through the host's shim 37, node 37, git 34; quint absent). With `PATH=/usr/bin:/bin:/usr/sbin:/sbin` the same Build took 1.23 CPU-s (user 0.55, sys 0.68) and about 0.6 s less wall.
  - Real-time waiting, a new executable: the acceptance step took 464 to 470 ms, against 11 ms when the same script had run before. On this host the first run of a newly written executable file takes 160 to 466 ms, and later runs 8 to 12 ms. A hard link or a symbolic link to an already run file takes 4 to 8 ms, and `sh <file>` 4 ms. `newEnvIn` writes a new `accept.sh` (and two reports) for every fixture project, so every fixture Build pays that first run.
  - Setup repeated by every test: `newEnv` takes 64 to 138 ms (about 10 git processes).
  - CPU in the test process itself: small. What remains is the Build's own git work (136 processes), which is product code and stays.
- `TestOneInvalidVerdictIsSentBackAndASecondEndsTheBuild` alone (27 Builds): 16.5 to 16.9 s. In a scratch copy with one shared acceptance script it took 15.4 s, and with that script and the system PATH 11.2 s (67 CPU-s down to 39).
- `TestOneInvalidVerdictIsSentBackAndASecondEndsTheBuild`, `TestRecoveryRefusals` and `TestAResumeStillRefusesEveryChangeToWhatIsStaged`, run back to back: 40.2 s wall (user 56.3 s, sys 73.2 s) at HEAD, against 25.2 s (user 33.9 s, sys 47.5 s) in that scratch copy.
- Already once per package, or already event-driven: the only helper binary is `cmd/kogen-build`, built once by `TestStandaloneBuildEvidence`. The git wrapper is written once by `TestMain`. The fake executors of `./build` (`newFakeExecutor`, `lineupExec`) are in-process, not processes. The held-child waits and the silent-shell waits were replaced by events and controlled time in 579e21a and 545a101; no remaining real-time wait of `./build` lies on a Build's path.
- The other packages are small: `consumes/kogen-coordinator` 7.3 s, `-executor` 1.1 s, `-loop` 4.9 s, `-review` 4.6 s, `-verification` 17.1 s, `contract` 4.1 s.

Required end state:

1. One shared, read-only acceptance fixture (`build/helper_test.go`, `build/main_test.go`). Once per run of the test binary, the package writes one acceptance script, with its green and red reports, into a private directory that `TestMain` creates before `m.Run` and removes after it (next to, or in place of, the git wrapper's directory). The reports are what `newEnvIn` writes today: `reportFor(t, project.FeaturePath(testSlug), testFeature, "PASSED")` and the same with `"FAILED"`. The script is today's text with the shared reports' paths: when `grep -qx red app.txt` holds it copies the red report to `$KOGEN_ACCEPTANCE_REPORT`, prints `actual-case-red` and exits 1, and otherwise it copies the green report. Its mode has no write permission (0o555). `newEnvIn` no longer writes `green.ndjson`, `red.ndjson` or `accept.sh` of its own. It hard-links `<aux>/accept.sh` to the shared script (`os.Link`) and fails the test when linking fails. The configured acceptance command stays exactly `filepath.Join(e.aux, "accept.sh")`, so the frozen goldens (which record `<aux>/accept.sh`) and the expectation `acceptance (<e.aux>/accept.sh): failed, exit status 1` of `TestRedVerificationIsFedBackToTheSameBuilderAndRepaired` do not change. No test writes through a fixture's `<aux>/accept.sh`. `TestSuccessiveModelIntentsKeepIndependentSpecifications`, which today overwrites it with its later Intent's script, first removes the link (or writes elsewhere and renames over it) and writes its own script there, with the same content, mode and checks as today. `state_golden_test.go` keeps reading the script through `KOGEN_GOLDEN_ACCEPT=<aux>/accept.sh`. The acceptance check overlays a file into package `build` that calls these test helpers, so they keep their names and meaning: `newEnv(t, ...) *env` with the fields `root` and `aux`, `physical`, `writeFile`, `reportFor`, `testSlug` and `testFeature`.
2. The package's test PATH (`build/main_test.go`). Before `m.Run`, `TestMain` sets the process PATH to a private directory followed by `/usr/bin:/bin:/usr/sbin:/sbin`. Every session, git command and standalone binary of the package's tests then gets that PATH, because `isolatedEnv` copies the process environment. The private directory holds exactly these wrappers, each written once, of the form of today's git wrapper (`#!/bin/sh` and `exec '<path>' "$@"`):
   - `git`: today's wrapper of the Command Line Tools git when `realGitDir` finds it, otherwise one that execs the git that `exec.LookPath` found at start;
   - `go`: execs `<GOROOT>/bin/go`, with GOROOT from one `go env GOROOT` at start (`TestStandaloneBuildEvidence` runs `go build`, and the named-feedback Builds run `go test`);
   - `node`: execs the path that one `node -p process.execPath` prints at start (the maintained-model and named-feedback tests).

   A tool not found at start gets no wrapper, and its tests behave as they do today without it. The check identity of every Build in these tests then runs only go, node, git and whatever the system directories hold, instead of every toolchain on the host's PATH. Tests that build their own PATH (`checkAttempt` in `checkreuse_test.go`) keep doing so. `TestMain`'s comment says what it now does.
3. Parallel tests. `t.Parallel()` becomes the first statement of `TestWholeIntentRedFeedbackEndsWithTheFinishReminder` (`build/named_feedback_test.go`), `TestStandaloneBuildEvidence` (`build/standalone_test.go`), `TestSuccessiveModelIntentsKeepIndependentSpecifications` (`build/maintained_test.go`), `TestUnmovedScopedFeedback` and `TestUnmovedExternalFeedback` (`build/unmoved_test.go`). Each uses only its own temporary folders, provider and fixtures, sets no environment variable and changes no working directory. The other non-parallel tests stay as they are, including `TestModelFreeBuildDoesNotCreateModelStorage`: each takes under 2.3 s, or uses `t.Setenv`.
4. Same defects caught. Every assertion and failure message of every test stays, at least as strict. Each changed test (and `TestRedVerificationIsFedBackToTheSameBuilderAndRepaired`, which exercises the shared script's red and green paths) still fails, with its own message and while running in parallel, against a deliberately broken implementation of what it checks. Acceptance scenario 3 applies each one to a temporary `-overlay` copy:

   | Test | Defect it catches | Broken implementation |
   | --- | --- | --- |
   | `TestWholeIntentRedFeedbackEndsWithTheFinishReminder` | red whole-Intent feedback to the builder lacks the finish reminder | `finish-reminder-dropped`: `verifyAndReview` (`build/builder.go`) returns the feedback without `"\n\n" + finishReminder` |
   | `TestStandaloneBuildEvidence` | kogen-build's JSON stdout drops the verification checks | `standalone-checks-dropped`: `cmd/kogen-build/main.go` sets `r.Checks = out.Checks[:0]` |
   | `TestSuccessiveModelIntentsKeepIndependentSpecifications` | a later model Intent's Build stops verifying the earlier Intent's maintained model | `maintained-models-dropped`: `build/build.go` sets `in.MaintainedModels = models[:0]` |
   | `TestUnmovedScopedFeedback` | two red stage passes with an unmoved failing set give no "Failing set did not move" notice | `unmoved-notice-dropped`: `unmovedNotice` (`build/unmoved.go`) returns "" |
   | `TestUnmovedExternalFeedback` | the same for an external builder | `unmoved-notice-dropped` |
   | `TestRedVerificationIsFedBackToTheSameBuilderAndRepaired` | a red pass that goes back to the builder is not counted as a repair | `red-repair-uncounted`: the red branch of `steps.Verify` (`build/route.go`) skips `b.Repairs++` |

   `TestNamedFeedbackBuilderRepair` runs go and node inside its Build's acceptance. It still passes under the new PATH (scenario 1), which shows that those tools stay reachable.
5. Unchanged: every file that is not a `_test.go` file under `build/` (product code, `cmd/kogen-build`, `consumes/`, `contract/`, `go.mod`, `go.sum`, `.kogen/project.yaml`), every golden under `build/testdata` (no `-update`), every CLI command and flag, config key and environment variable, and every timeout, limit and deadline (no `-timeout`, no alarm change in `TestMain`). No test-only seam is added, and no test is deleted.
6. Report. The Build's finish summary gives the profile above, updated with anything the Build measured differently. It repeats the table under rule 4 with the result of each broken-implementation run. It reports the wall time of `./build` before and after the change, measured on the same host at the same load: `GOFLAGS=-trimpath go test -count=1 ./build` under `/usr/bin/time -p` (real, user and sys), on the start tree and on the candidate, back to back, with `uptime`'s load averages next to each. Both runs use copies outside the checkout, so that a host wrapper that queues test runs started inside work trees adds no waiting to either. For the start tree, extract `git archive HEAD` into a new temporary directory. For the candidate, copy the candidate tree. Copy `testdata/tools/cucumber/node_modules` into each. No Git state changes.

## Decisions
- The profile names, for the slowest tests and for one simulated Build, how much is CPU, process start, setup repeated by every test, and real-time waiting. It is recorded above from measurements on the request's host, and the Build's report repeats it with the before/after package times. (source: request)
- The largest costs that the tests own are removed: the toolchain probes of every verification pass (by giving the tests' Builds a PATH of the tools the tests use), the first-run wait of a new acceptance script in every fixture project (by one shared, immutable acceptance fixture), and the 32 s in which slow tests ran alone (by `t.Parallel`). The Build's own git work is product behaviour and stays. (source: request)
- Every changed test is stated with the defect it catches, and is shown failing against a deliberately broken implementation. No assertion is deleted or weakened, and no timeout, limit or deadline is raised. There is no new CLI command, flag, config key or environment variable, and no test-only seam. The stand-in toolchains and the broken implementations are synthetic and temporary. (source: request)
- Before/after wall time of the changed package (`./build`) is reported, measured on the same host at the same load. (source: request)

## Tests
- Builds started by the package's tests run none of the host's other toolchains, and go and node stay reachable inside them: update `TestMain` (`build/main_test.go`); acceptance scenario 1 runs `TestTheReviewerApprovesUnchangedCodeWithoutRepairs` and `TestNamedFeedbackBuilderRepair` with logging stand-ins for elixir, erl, mix, ruby, bundle, python3, npm and quint first on PATH, and requires both to pass with no stand-in run (today all eight run in every verification pass) (integration)
- Every fixture project runs one shared, read-only acceptance script as `<aux>/accept.sh`, red for a red `app.txt` and green otherwise: update `newEnvIn` and `TestMain`; acceptance scenario 2 overlays the Go source held in `k-go-suite-profile__shared.js` into package `build`; its check makes two projects with `newEnv` (integration)
- A test that needs another acceptance script replaces its fixture's link instead of writing through it: update `TestSuccessiveModelIntentsKeepIndependentSpecifications` (integration)
- The five slow tests that ran alone run in parallel: add `t.Parallel()`; acceptance scenario 3 requires each to have paused for a parallel slot, and the configured go-test check requires them to pass (scenario)
- Each changed test still fails, in parallel and with its own message, against the broken implementation named under rule 4: acceptance scenario 3 (regression)
- Product code, goldens, the CLI, config keys, environment variables, timeouts and every other assertion stay unchanged: the existing `build`, `consumes`, `contract` and `cmd/kogen-build` tests pass without `-update` (existing)
