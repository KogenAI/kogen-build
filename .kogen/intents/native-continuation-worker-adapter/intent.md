# Add native Build continuation worker adapter

Provide the native Build continuation adapter maintained by kogen-build for a factory worker continuing a stopped, still-owned Build. Library and standalone preparation produce model-free evidence; execution rechecks that evidence under the ordinary native Build lock and delegates to supported native resume. Replace reliance on optimistic inspect availability with an authoritative, specific held reason; do not remove the existing inspect facts or change supported resume states. The consumer is the private fleet dispatcher and worker used for stack.menu's sponsors draft and other customers' saved Builds, not a new scheduler in this repository.

Preparation exposes the exact requested Build, host-bound checkout, saved and current checkout identity, candidate tree, approved contract, approval, request and checkpoint identities, stage, remaining roles and checks, and the native refusal detail. The plan is evidence only. Execution requires the existing fleet's fresh fenced claim, host, attempt, request revision/hash and ordinary provider/finishing admission. The fleet keeps its policy, account credentials, provider selection, scheduling and landing policy; native Build keeps its ordinary verification, independent review and commit gates. No product allowlist, inode rebinding, work reconstruction or gate bypass is added. The sponsors row remains held; the separate reconstruction item remains the unusable-checkout case. This does not deliver or mark delivered the sponsors feature, mutate customer records, transfer a checkout or integrate the private fleet's implementation.

## Interface contract

Add exported value types in package build and document their use in README.md and the producer contract. The callable library interface is:

```go
func (in ResumeInput) PrepareContinuation(ctx context.Context, s *sys.Session, binding ContinuationBinding) (ContinuationPlan, error)
func (in ResumeInput) ExecuteContinuation(ctx context.Context, s *sys.Session, plan ContinuationPlan, fresh ContinuationBinding, admit func(context.Context, ContinuationPlan, ContinuationBinding) error) (int, error)
```

ContinuationBinding has string fields Host, Claim, Attempt, RequestRevision, RequestHash, with JSON keys host, claim, attempt, request_revision, request_hash. These are non-secret identity/fencing evidence from the caller, not credentials. Preparation echoes them without claiming they were authorized. This repository has no authoritative fleet request revision store: native approval/contract/source identities must remain separate from the caller's request binding. Native code must not manufacture a fleet claim, reservation, revision or permission.

ContinuationPlan has string fields BuildID, Slug, Root, CheckoutIdentity, SavedCheckoutIdentity, CandidateTree, Start, ApprovalSHA256, ContractSHA256, CheckpointSHA256, Stage, HeldReason, with JSON keys build_id, slug, root, checkout_identity, saved_checkout_identity, candidate_tree, start, approval_sha256, contract_sha256, checkpoint_sha256, stage, held_reason. It also has Binding (ContinuationBinding, JSON binding), RequiredRoles ([]string, JSON required_roles), RequiredChecks ([]string, JSON required_checks). Keep empty lists as JSON arrays. Additional evidence needed to bind the native validation result, such as staged custody, source provenance or scoped-stage progress, may be represented explicitly, without exposing credentials or raw model history. Do not confuse saved candidate identity with current working tree identity on a held drift. ContractSHA256 is project.Hash over the approved baseline. ApprovalSHA256 and CheckpointSHA256 hash the exact files' bytes; expose known saved identities even when current validation refuses. A missing or malformed checkpoint returns only facts actually observed, not invented identities.

Prepare returns the plan even on native refusal, plus the same structured error/detail as native resume. HeldReason is that native error detail, empty only when native continuation is supported at the observed state. Derive readback and execution from the same native resume validation, not a second approximate implementation or the facts resume_status. Preserve current refusal precedence, filesystem device/inode checks, source provenance, approved bytes/baseline/configuration, Intent identity, index staged equivalence (including allowed stat refresh), candidate drift exceptions, working-context custody, stage validation and executor capabilities. Preparation stops before StartRun, facts/checkpoint writes, provider credential/login activity, executor start, admission callback or any checkout mutation. It may use private temporary Git state to compute evidence, never stage, reset or repair the checkout. It reports remaining work, not a waiver of ordinary gates.

RequiredRoles identifies model roles that native routing can still require, in native role order; a native builder checkpoint exposes build then review. RequiredChecks lists still-required configured check command strings in configured order, allowing reuse only as native verification already supports it. Document the remaining native acceptance/model, scoped-stage, review and finishing obligations as evidence as appropriate; configured check commands are not a replacement for those gates. An already-landed checkpoint remains native's idempotent no-op and must not be advertised as unfinished model work. Unsupported/uncertain boundaries remain held, not newly resumable.

Execute first acquires the ordinary native Build lock, reruns the shared native validation and compares the prepared native identities and binding with the fresh observed evidence and supplied fresh binding. It refuses stale plans and mismatched host, claim, attempt, revision or hash without repairing or overwriting evidence. After successful comparison and before any new native run or paid request, it requires a non-nil admission callback and calls it under that same lock with the evidence and fresh binding. The callback is a trusted worker integration seam: the existing fleet must freshly validate/consume its fenced claim and ordinary admission there, and reject duplicate or no-longer-owned attempts. Callback error is a held pre-execution refusal. It must not be invoked during preparation. Do not add a local queue, claim ledger or substitute authorization flag. After admission, continue through the supported native resume execution path while retaining the lock, without a release/reacquire gap and without bypassing provider admission or finishing gates. Return ordinary Build phase exit/error and populate Outcome as native Resume does. Duplicate protection includes the fleet fence for duplicates that stop before landing; native moved-HEAD/already-landed behavior alone is not a duplicate fence. Preserve existing Build, Resume and Recover behavior.

Standalone interface: build the existing cmd/kogen-build entry point, then use `prepare-continuation --project <checkout> --id <build-id> --binding <JSON-file>`. This is model-free, accepts the binding object above, and returns the ordinary single JSON result envelope extended with continuation containing the plan. Preparation success uses exit_code/process status 0; a held native refusal uses 1 and the native structured category/kind/message, still including the partial/complete plan. Keep stderr diagnostics and stdout JSON separation. Existing build/resume output and argument validation remain compatible. There is no CLI switch that grants fleet authority.
