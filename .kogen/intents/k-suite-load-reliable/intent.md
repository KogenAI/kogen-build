# Wait for held children by event in build tests

Slug: k-suite-load-reliable
Model: not applicable — only test waits and test fixtures of ./build change; kogen-build's product code, state and rules do not
Acceptance:
- .kogen/intents/k-suite-load-reliable/acceptance.feature
- features/steps/k-suite-load-reliable__steps.js
- features/steps/k-suite-load-reliable__control.js

Twelve tests of `./build` start a Build (or a native round), wait until its held child runs, and then interrupt or stop it. The held child is a setup command, a baseline check, a builder or reviewer shell call, a stage gate, a verification check or a post-commit hook. Today each wait polls a marker file under a fixed wall-clock deadline of 5 to 120 seconds. On a busy host the Build is still doing real work (git, verification) when the deadline passes, and the test fails although nothing is wrong. Example from the host's Build logs: `--- FAIL: TestACommitInterruptedDuringPostcommitIsUndone (16.09s)` with `timed out waiting for .../hook-waiting`. After this change each of these tests waits on the event it needs. It continues once the held child is running, and fails once the Build (or round) has ended first. There is no deadline. Every assertion after the wait stays as it is. Only `_test.go` files under `build/` change.

What holds at HEAD b05e5e3:
- `waitForRunning(t, path, done, a, limit)` (`build/commit_test.go`) polls `path` every 20 ms until `limit` has passed. It fails `build ended before <path> appeared: <shown>` when `done` closes first, and `timed out waiting for <path>` when the limit passes.
- `waitFor(t, path)` (same file) polls 750 times every 20 ms, about 15 s. It fails `timed out waiting for <path>`.
- `TestNativeShellContextCancellationStops` (`build/executor_native_test.go`) polls for its marker under a 5-second deadline (`shell did not start`).
- `TestErrorStopDuringBaselineCheckNamesTheBaseline` (`build/baseline_wall_test.go`) polls under a 15-second deadline (`the baseline check never started`).
- Both baseline-stop tests in `build/baseline_wall_test.go` then sleep `time.Sleep(200 * time.Millisecond)` before they stop the Build.
- Three native-executor tests hold their shell child with `sleep 30`, so the child ends by itself after 30 s.

Required end state:

1. Build waits. `waitForRunning` loses its `limit` parameter and its deadline. It returns once `path` exists. It fails with the unchanged message `build ended before <path> appeared: <shown>` once the Build's `done` has closed and `path` still does not exist. It never fails on elapsed time. A polling interval is allowed: it only rechecks the two events. Its doc comment no longer mentions a deadline. Its eight callers drop their limit arguments:
   - in `build/commit_test.go`: `TestAnInterruptedStartupRestoresTheIndexAndCannotResume` (15 s) and `TestACommitInterruptedDuringPostcommitIsUndone` (15 s);
   - `TestResumeRefusesAnUncertainToolBoundary` (10 s, `build/resume_test.go`);
   - `TestInterruptingAStageGateRetainsNoCompletedEvidenceAndResumeRerunsSetupAndCommands` (15 s, `build/stages_test.go`);
   - in `build/review_test.go`: `TestAnInterruptedTargetedRepairReportsPendingReviewAndChangedVerification` (30 s) and `TestAnInterruptedVerificationOfAReviewerRepairResumesWithoutANewRequest` (30 s);
   - `TestExternalBuilderReviewStageResumes` (120 s, `build/review_resume_external_test.go`);
   - `TestInterruptedBaselineCheckNamesTheBaseline` (15 s).

   `TestErrorStopDuringBaselineCheckNamesTheBaseline` replaces its own 15-second loop with the same rule. It continues once its marker exists, and fails, naming the marker and `buildRun`'s returned error, once `buildRun` has returned first.
2. Native round waits. In `TestNativeRoundMapsCancellationButKeepsTheSessionsInterrupt`, `TestNativeShellContextCancellationStops` and `TestChecktimeClockReadiness` (both subtests), the wait continues once the marker exists. It fails with the round's returned error once the round has returned first. There is no `waitFor` cap and no 5-second deadline. `TestNativeShellContextCancellationStops` cancels its context before it fails, as today. `TestChecktimeClockReadiness` keeps its check that the round is still held after the marker appeared (`the shell child was not held`). `waitFor` is removed or changed, so that no caller keeps a deadline.
3. Held children. The `sleep 30` in the shell commands of those three tests is replaced. The command writes its marker as today, then waits for a release file under a `t.TempDir()` outside the checkout root (for example `while [ ! -e '<release>' ]; do sleep 0.05; done`), so the child never ends by itself while the test holds it. The release file is created by a `t.Cleanup` registered before the test's own interrupt/cancel-and-join cleanup. Because cleanups run last-registered-first, the release happens only after that cleanup has stopped and joined the round. A release therefore never lets a held round continue, and no child outlives its test. The `sleep 600` children of the other tests stay: they outlast go test's 10-minute package alarm, so they cannot end before their test does.
4. The two `time.Sleep(200 * time.Millisecond)` in `build/baseline_wall_test.go` are removed. No assertion needs time to pass: `recordBaseline` (`build/baseline.go`) sets `baselineRunning` before it starts the check's command, so once the check's marker exists the Build is inside that check, and `wall_ms` has no lower bound in the assertions.
5. Same defects caught. Every assertion and failure message after each wait stays, and is at least as strict. A Build that ends before its held child runs still fails the test, as before. A Build that never reaches its held child also still fails: go test's package alarm stops it and names the running test, where the old deadline failed after 5 to 120 s. Each changed test still fails, with its own assertion's message, against a deliberately broken implementation of what it checks. Acceptance scenario 2 names each break, and applies it to a temporary copy: an `-overlay` file for this module, or a `-modfile` copy for kogen-coordinator.

   | Changed test | Defect it catches | Broken implementation that still fails it |
   | --- | --- | --- |
   | `TestACommitInterruptedDuringPostcommitIsUndone` | an interrupt during `git commit` leaves the commit on HEAD | `interrupted-commit-kept` |
   | `TestAnInterruptedStartupRestoresTheIndexAndCannotResume` | resume does not refuse an interrupted startup | `uncertain-boundary-resumed` |
   | `TestResumeRefusesAnUncertainToolBoundary` | resume does not refuse a builder shell call that was interrupted | `uncertain-boundary-resumed` |
   | `TestAnInterruptedTargetedRepairReportsPendingReviewAndChangedVerification` | resume does not refuse a reviewer shell call that was interrupted | `uncertain-boundary-resumed` |
   | `TestInterruptingAStageGateRetainsNoCompletedEvidenceAndResumeRerunsSetupAndCommands` | a Build stopped in its stage gate cannot be resumed to rerun the gate | `every-stage-refused` |
   | `TestExternalBuilderReviewStageResumes` | an external builder's Build stopped in review verification cannot resume and land | `every-stage-refused` |
   | `TestAnInterruptedVerificationOfAReviewerRepairResumesWithoutANewRequest` | a native Build stopped in review verification cannot resume and land | `every-stage-refused` |
   | `TestInterruptedBaselineCheckNamesTheBaseline` | an interrupt during a baseline check does not name the check | `baseline-stop-unnamed` |
   | `TestErrorStopDuringBaselineCheckNamesTheBaseline` | an error stop during a baseline check does not name the check | `baseline-stop-unnamed` |
   | `TestNativeRoundMapsCancellationButKeepsTheSessionsInterrupt` | a native round loses its session's interrupt and signal | `native-interrupt-lost` |
   | `TestChecktimeClockReadiness` | a native round loses its session's interrupt and signal | `native-interrupt-lost` |
   | `TestNativeShellContextCancellationStops` | a cancelled native round reports success | `native-cancel-succeeds` |
6. Unchanged:
   - every file that is not a `_test.go` file under `build/` (including `go.mod`, `go.sum`, `cmd/kogen-build`, `consumes/`, `contract/` and `.kogen/project.yaml`);
   - every CLI command and flag, config key and environment variable;
   - every timeout, limit and deadline, including go test's 10-minute package alarm: no `-timeout`, and no alarm change in `TestMain`;
   - every other test.

   No test-only seam is added: none is needed.
7. Report. The Build's finish summary repeats the table under rule 5 together with the result of each broken-implementation run. It also reports the wall time of the changed package before and after the change, measured on the same host at the same load. Run `GOFLAGS=-trimpath go test -count=1 ./build` back to back on the start tree and on the candidate, with `uptime`'s load averages next to each. For the start tree, extract `git archive HEAD` into a new temporary directory outside the checkout and copy `testdata/tools/cucumber/node_modules` into it. No Git state changes.

## Decisions
- The tests in scope are the ones found failing under load, as the request directs: from the red baselines' go-test output and from a run while the host is busy. Each one waits on the event it needs, never on a wall-clock margin. Here those are the twelve held-child waits of `./build` named under rules 1 and 2. (source: request)
- Every changed test is stated with the defect it catches, and is shown failing against a deliberately broken implementation. No assertion is deleted or weakened, and no timeout, limit or deadline is raised. There is no new CLI command, flag, config key or environment variable. Regression cases are synthetic. (source: request)
- Before and after wall time of the changed package is reported, measured on the same host at the same load. (source: request)

## Tests
- A test that waits for a Build's held child continues once the child runs and fails once the Build ends first, with no wall-clock deadline, reproduced by delaying every git call 0.25 s or 1 s, which fails eight of these nine tests today (acceptance delays it 0.25 s for `TestACommitInterruptedDuringPostcommitIsUndone` and `TestResumeRefusesAnUncertainToolBoundary`): update `waitForRunning`, its eight callers and `TestErrorStopDuringBaselineCheckNamesTheBaseline` (regression)
- A test that waits for a native round's held shell child continues once the child runs, fails once the round returns first, and holds the child until its own cleanup has stopped the round, reproduced by delaying every git call 0.5 s, which fails `TestNativeShellContextCancellationStops` today: update `TestNativeRoundMapsCancellationButKeepsTheSessionsInterrupt`, `TestNativeShellContextCancellationStops` and `TestChecktimeClockReadiness` (regression)
- The baseline-stop tests stop the Build without the 200 ms sleeps and keep every assertion: update `TestInterruptedBaselineCheckNamesTheBaseline` and `TestErrorStopDuringBaselineCheckNamesTheBaseline` (regression)
- `TestACommitInterruptedDuringPostcommitIsUndone`, `TestResumeRefusesAnUncertainToolBoundary` and `TestNativeShellContextCancellationStops` pass under the delayed git: acceptance scenario 1 (scenario)
- Each changed test still fails, with its own assertion's message, against the deliberately broken implementation named in the table under rule 5: acceptance scenario 2 (scenario)
- Product behaviour, the CLI, config keys, environment variables, timeouts, go.mod and every other test stay unchanged: the existing `build`, `cmd/kogen-build`, `consumes` and `contract` tests pass (existing)
