# Keep Build edits out of shared test support

Slug: build-leaves-shared-test-support-unedited
Model: not applicable — the change is brief text plus a pure function of two Git trees and the README, with no state
Acceptance:
- .kogen/intents/build-leaves-shared-test-support-unedited/acceptance.feature
- features/steps/build-leaves-shared-test-support-unedited__steps.js
- features/steps/build-leaves-shared-test-support-unedited__driver/fixture_test.go.txt

Builds edit files that every test loads (the test entry or bootstrap file, shared helper and support modules, the test-environment configuration, dependency manifests) to make their own tests pass, which breaks other tests and result collection. Observed in the lab: the grader's protected-paths check reported `TAMPER: test/test_helpers/session_test_helper.rb differs` in 33 of 76 graded cells, typically because a Build changed the shared helper's cookie deletion from `cookies.delete :session_token` to `cookies.delete "session_token"` instead of handling the switch inside its own test file; in three cells an edit of `test/test_helper.rb` switched the suite's output format and the results file was never written. This Intent adds advice to the Build brief and a line to the landed summary, in package `build` only. It does not block a landing, adds no configuration, and an Intent that names a shared file keeps working.

Rules:
- Brief text. The builder brief states, in the `# Protected paths` section of the Stable part of `Attempt.brief` (a new constant in `build/prompt_text.go` placed after `manifestNotice`) and as a rule in `build/prompts/builder.md`, that files shared by every test (the suite's entry or bootstrap file, shared helper and support modules, the test-environment configuration and dependency manifests) are not edited unless the Intent names them, and that when the Build needs different behaviour from a shared helper it adds a helper beside its own new test files (a new file, a local override, or inline code in the test) and leaves the shared file byte-identical. The pinned literals are: the sentence `Shared test support is not edited unless the Intent names it`, the phrase `beside your own new test files` and the word `byte-identical`; the rest of the wording is free. The model-facing goldens that record the brief and the builder instructions are regenerated deliberately (`go test ./... -update`) and their diff reviewed.
- Which paths are test support. Computed against the Build's start commit (`Attempt.Start`), never the working tree. (1) The project's own listing: if the README.md at the start commit has any line that contains `test support` (case-insensitive) and names a tracked path of the start commit as an exact path (bounded by start or end of line, whitespace, backtick, quote, parenthesis, comma, colon or semicolon), those named paths are the test support and nothing else is. (2) Otherwise, the files that the unchanged tests require first: for every tracked test file of the start commit (a file under `test/`, `tests/` or `spec/`, or whose base name starts with `test_` or ends with `_test.<ext>` or `_spec.<ext>`), take its first line that is `require`, `require_relative` or `load` followed by a quoted string; resolve the string to a tracked start-commit file (a `require_relative` string against the file's own directory; a `require` string against the repository root and the directories `test/`, `spec/` and `lib/`, trying the string as is and with the extensions `.rb`, `.exs`, `.py`, `.js`); the resolved file is test support, and so is every file that such a file itself requires or loads by the same rule (repeated until no new file appears). Unresolvable strings (libraries, paths outside the repository) are ignored. In this fallback, the dependency manifests `Gemfile`, `Gemfile.lock`, `package.json`, `package-lock.json`, `go.mod`, `go.sum`, `mix.exs`, `mix.lock`, `pyproject.toml`, `requirements.txt` and the test-environment configuration `config/environments/test.rb`, when tracked at the start commit, are also test support, because the request names them as shared by every test. Everything in this rule is a constant, not a setting.
- Summary line. When the committed tree differs from the start commit in a path that is test support (modified or deleted; a path that did not exist at the start commit never counts), the landed summary has exactly one line `  shared test support changed: <paths>` (two leading spaces like the other summary lines; paths sorted ascending by byte order, joined by `, `, all of them, no cap), written after the `  review repaired:` line when there is one, otherwise after the `  review: approved` line and its notes, and before the `  repairs:` line. A Build whose diff adds only new files, or changes only paths that are not test support, has no such line. It is written on the same landing path whether the Build landed in one run or after a resume.
- Replaces nothing; removes nothing.

## Decisions
- The README listing wins over the require-first fallback: when README.md names any test support path, only those paths count; the fallback applies only when it names none. The request says detection is by the project's own convention first (the paths the project instructions or setup name as test support) and otherwise the files that the unchanged tests require first. (assumption: the user accepts a README line containing `test support` that names a tracked path as the project's own listing) (source: request)
- The fallback follows the request: test support is what the unchanged tests require first (first require line of each test file, followed through the support files' own requires). The dependency manifests and `config/environments/test.rb` are added by name because the request lists them as shared files that tests load without requiring them first. (assumption: the user accepts the `require`/`require_relative`/`load` quoted-string form and the fixed manifest names as how "require first" is read across languages) (source: request)
- The comparison is start commit versus committed tree via the existing `b.repo.Changed` and the start commit's file list (`git ls-tree -r --name-only`), so new files never count and the Build's own README edits cannot change what counts. (evidence: build/commit.go; build/builder.go) (source: request)
- Advisory only: no refusal, no setting, no environment variable; the Intent naming a shared file does not suppress the summary line. (evidence: build/commit.go) (source: request)
- The regression test the Build writes must not use the `TestAcceptance` name prefix, which the acceptance fixture owns. (source: request)

## Source comparison
