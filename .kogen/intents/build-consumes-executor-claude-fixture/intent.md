# Use the Executor Claude fixture in Build tests

Slug: build-consumes-executor-claude-fixture
Model: not applicable — only kogen-build's test code and its dependency pin change; Build gains no state, rule or behavior
Acceptance:
- .kogen/intents/build-consumes-executor-claude-fixture/acceptance.feature
- features/steps/build-consumes-executor-claude-fixture__steps.js
- features/steps/build-consumes-executor-claude-fixture__observer.js

kogen-build's `build/context_external_test.go` carries its own copy of a fake `claude` runtime: the `fakeClaudeScript` shell script, and `withClaudeProcess`, which writes it at the managed runtime path and serves a local manifest origin through `claudecode.SeamEnv`. kogen-executor now owns one signed, shared fake Claude runtime for tests, `testkit/clauderuntime`, so this Build migrates that copy to it. The Build requires the signed kogen-executor main revision that carries the fixture, resolved through the ordinary Go dependency path (`go get` and `go mod tidy`), and `TestContextExternalFirstPrompt` runs the real Claude Code adapter on the fixture instead of on its own script. The duplicated script, its manifest origin and its `t.Setenv` are removed.

Everything else stays as it is: Build's own round behavior, spend and artifact assertions (`TestContextExternalReviewMatrix`, `TestContextExternalNativeBytes` and the frozen golden `build/testdata/context-external-golden.json`), the first-prompt assertions of `TestContextExternalFirstPrompt`, and the in-process fake Executor implementations (`lineupExec`, `fakeExecutor`) that test a different boundary and are not migrated. A new control, `TestContextExternalMalformedRuntimeResult`, feeds the fixture a malformed round result and requires the Build to stop with the adapter's refusal after one round and no commit; it must fail when the adapter tolerates such a line. Only `go.mod`, `go.sum` and `build/context_external*_test.go` change. kogen-executor (the producer), kogen-setup and kogen are not edited.

## Tests
- Build pins the signed Executor revision that carries the fixture and only its tests import it: acceptance scenario "Build resolves the signed Executor main revision that carries the fixture", with `go list` on go.mod (integration)
- The duplicated runtime script is gone, the first-prompt assertions and the in-process fakes remain and no other file changed: acceptance scenario "The duplicated runtime script is gone and the in-process fakes stay" (integration)
- The context/external tests keep passing on the fixture: update `TestContextExternalFirstPrompt` to use `clauderuntime.Install` and run `TestContextExternalFirstPrompt`, `TestContextExternalReviewMatrix` and `TestContextExternalNativeBytes` unchanged otherwise (existing)
- A malformed fake runtime result stops the Build after one round without a commit, and the control fails when the adapter tolerates it: add `TestContextExternalMalformedRuntimeResult` (integration)
- The rest of Build is unchanged: the configured go build, go vet and go test checks with the full Build suite (existing)
