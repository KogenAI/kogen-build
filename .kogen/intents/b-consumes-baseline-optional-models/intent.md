Paired consumer row of kogen-coordinator's Build coord-baseline-optional-files-when-present (candidates 285e710 and cd8b879). That change deliberately changes the shared baseline format: `project.Baseline` (`project/baseline.go`) leaves `.kogen/models.yaml` out of the baseline when the project has no such file (tracked, or untracked and not ignored: it asks `git ls-files -z --cached --others --exclude-standard -- .kogen/models.yaml`). The version `go.mod` pins today (`github.com/KogenAI/kogen-coordinator v0.0.0-20261105001101-4116df40cbf1`) always lists it right after `.kogen/project.yaml`. This repository's fixtures have no `.kogen/models.yaml`, so with the change their baseline list and hash change, and the consumer contract checks (4 Nov 22:38Z and 5 Nov 09:20Z, identical sets) refused it with these new failures here:
- `TestKReviewRetryUnchangedValidRequests/approve_lands` and `/changes_is_a_substantive_blocker`: the golden `approve.wire.json` / `changes.wire.json` request bytes, `k_reviewretry_valid_test.go:73/104`;
- `TestLegacyResumeRefusals` (4 subtests) and `TestMain76BuildsResumeAndLand` (9 subtests): `candidate/resume_refused … baseline/configuration changed`;
- `TestMain76ExternallyRepairedBlockedReviewReopensUnderTheSameReviewer` (2 subtests);
- `TestNamedFeedbackCompatibility`: the passing Build's first request changed.

After this change these tests pass both against the pinned coordinator and against one with the absent-file rule. This row lands first; the producer is then re-shaped on top. No pin and no product behavior changes: only `_test.go` files under `build/` and the golden `build/testdata/named-feedback-compat.json` change.

What holds now (inspected at HEAD 8dbf8de, and reproduced with a copy of the pinned coordinator module carrying exactly the producer's absent-file rule, see Feasibility):
- `newEnv`/`newEnvIn` (`build/helper_test.go`) make a fixture repository whose "fixture baseline" commit holds `README.md`, `app.txt`, `.gitignore` and `.kogen/project.yaml`, and no `.kogen/models.yaml`. The first review request recorded in `build/testdata/reviewretry/approve.wire.json` and `changes.wire.json` names the protected files as `…, .kogen/project.yaml, .kogen/models.yaml.`, and `build/testdata/named-feedback-compat.json` names them the same way; with the absent-file rule the lineup file drops out of that list and the bytes differ. `sameWireFixture` and `TestNamedFeedbackCompatibility` compare through `withLineupFile` (`build/lineup_layout_test.go`), which is the identity with both coordinators above (`lineupMoved` is false for both: they still read `models:` from `.kogen/project.yaml`).
- The legacy tests build their checkpoints from Elixir-generated fixtures (`build/testdata/legacy/`, `build/testdata/legacy76/`), whose fixture projects have no `.kogen/models.yaml` and whose recorded baselines do not list it. `legacyAdaptBaseline` (`build/legacy_test.go`, called from `newLegacyEnv` and from `newLegacy76Env` in `build/legacy76_test.go`) always inserts `.kogen/models.yaml` after `.kogen/project.yaml` with the digest atom `missing`. Resume (`build/resume.go`) compares the saved baseline with `project.Baseline` of the checkout and refuses `baseline/configuration changed` when they differ, so with the absent-file rule every resume of an adapted checkpoint is refused. These fixtures cannot be regenerated from a project with a lineup file: they come from the Elixir Kogen, which never listed the file, and `newLegacy76Env` checks that the fixture's landed commit equals the Elixir commit id.
