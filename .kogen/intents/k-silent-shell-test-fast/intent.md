# Run the silent-shell tests on controlled time

Slug: k-silent-shell-test-fast
Model: not applicable — a test-only time seam passed through to the loop's existing shell wait; kogen-build gains no state or interacting rules
Acceptance:
- .kogen/intents/k-silent-shell-test-fast/acceptance.feature
- features/steps/k-silent-shell-test-fast__steps.js
- features/steps/k-silent-shell-test-fast__control.js

`TestSilentBuildShellNotStopped` and `TestSilentReviewShellNotStopped` in `build/silent_shell_test.go` stop sleeping for real. Today both run `silentCommand = "sleep 47; printf 'done\n'"` so that it outlasts the loop's 45-second shell wait. Each test therefore spends about 47 s of real time. They now drive the loop's real shell wait on controlled time, through the loop's test-only seam `tools.Tools.ShellAfter`. Their coverage stays the same. A native shell call (the builder's, or the reviewer's) writes nothing until its wait elapses. It then yields a `running` result with a handle, and the command keeps running. Retrieving the handle returns `completed`, with exit status 0 and the later output `done\n`. The Build lands one commit, and its run log has no `command_no_progress` event.

What holds at HEAD b07372f: go.mod pins `github.com/KogenAI/kogen-loop v0.0.0-20261104223449-7e80986bcd04`. That is kogen-loop's main of 2026-11-04 22:34Z, and it contains the intents `l-shell-wait-seam` and `l-shell-wait-seam-rest`. At `tools/tools.go:1011-1030` of that pin, the shell wait is 45 s for a new command and 30 s for a handle retrieval. When `ShellAfter` is set, the shell call passes that wait to `ShellAfter`, starts no timer, and treats a value received from the returned channel as the wait elapsing. Production leaves it nil and keeps the real timer. kogen-build builds its native tools in two places: the builder at `build/executor_native.go:125` and the reviewer's `review.Tools.Native` at `build/host.go:74`. Neither sets `ShellAfter` today.

Required end state:

1. The seam. `Deps` (`build/hooks.go`) gets one unexported field, `shellAfter func(wait time.Duration) <-chan time.Time`. Its doc comment says it is a test seam that production leaves nil, and that it is no CLI flag, `project.yaml` key, environment variable or checkpoint field. Both `tools.Tools` literals, at `build/executor_native.go:125` and `build/host.go:74`, pass it as `ShellAfter: b.deps.shellAfter`. Nothing else reads or sets it. Because the field is unexported, `cmd/kogen-build` and any other module cannot set it; only tests in package `build` can. `Build` and `Resume` take it from their own `Deps`, as they already do with the other fields. With the field nil, behaviour and bytes are what they are today: the real 45 s and 30 s timers.
2. The two tests (`build/silent_shell_test.go`). Each test gets its own controlled clock, set on its own `Input` through the existing `e.build(...)` and `e.reviewed(...)` mutators, for example `func(in *Input) { in.shellAfter = clock.after }`. There is no package-level variable, because both tests are `t.Parallel()`. The silent command writes nothing until the test releases it, then prints `done\n` and exits 0. One way: it waits for a release file under a `t.TempDir()` outside the repository, so the candidate tree stays clean, and `t.Cleanup` creates that file so the command never outlives a failed test. The clock fires the first wait it is asked for (the new command's wait) at once, while the command is still running and silent. Only when a later wait is asked for (the handle retrieval's) does it release the command; it never fires that later wait itself. The retrieval then returns when the command completes. The clock does not assume the 45 s or 30 s values, so the tests stay correct if the loop's waits change. `silentCommand = "sleep 47; ..."` and every real sleep of the silent period are removed. Every existing assertion stays at least as strict:
   - `continueSilent`'s checks: a `running` result with a stable non-empty handle, then `completed` with that handle, exit status 0 and output `done\n`;
   - exit 0 and no error;
   - exactly one new commit;
   - at least 3 provider requests (Build) or review requests (review);
   - no `command_no_progress` event.

   The file comment no longer claims a 45-second wait or a command that outlasts it in real time.
3. The consumes suite. The convention in `consumes/README.md` is that a suite pins every producer item kogen-build relies on, so the new use `tools.Tools.ShellAfter` is pinned in `consumes/kogen-loop` (for example in `tools_test.go`). The test pins its type `func(time.Duration) <-chan time.Time` at compile time. Through a real shell call it also asserts what kogen-build relies on: a value sent on the channel `ShellAfter` returned yields a `running` JSON result with a non-empty handle while the command still runs, and retrieving that handle after the command finishes returns `completed` with the command's later output. The Inventory gets a `tools.Tools.ShellAfter` row naming that test, and the use counts in "How coverage was checked" grow by this one kogen-loop use.
4. Unchanged: go.mod and go.sum (no re-pin), `cmd/kogen-build`, every CLI command and flag, `project.yaml` keys, environment variables, checkpoints, records and outputs. No timeout is raised. No other test changes, apart from the consumes addition above.

## Decisions
- The test-only time seam is a Go-level field set only by package `build` tests (the unexported `Deps.shellAfter`). It reaches the loop's existing `tools.Tools.ShellAfter`. It is never a CLI flag, config key or environment variable. (source: request)
- Both silent-shell tests are in scope: `TestSilentBuildShellNotStopped` and `TestSilentReviewShellNotStopped`. (source: request)
- The request's re-pin is already satisfied, as reconciled under Source comparison: the pinned kogen-loop 7e80986 contains the requested seam, `l-shell-wait-seam` (b099dfa) and `l-shell-wait-seam-rest` (fe2bcd7). Moving to fe2bcd7 itself would be a downgrade, so go.mod and go.sum stay unchanged. (source: request)
- The requested 2-second bound, as reconciled under Source comparison, applies to the time each silent-shell test spends beyond the same harness's plain landing test. It is measured one test at a time in one `go test` run: `TestBuildLandsOneCommitWithTheIntentTrailer` for the Build test and `TestTheReviewerApprovesUnchangedCodeWithoutRepairs` for the review test. (source: request)

## Source comparison
- Addressed: "The test runs in under 2 seconds" and "Test-suite speed is the owner's first priority". The 47 s silent period is replaced by controlled time (rules 1 and 2; both scenarios, steps 1-3). Conflict, reconciled: on this runner the fixture harness alone already takes about 2 s per test, without any shell call. Measured alone with `GOFLAGS=-trimpath go test -count=1 -v -run '^<name>$' ./build` at HEAD, `TestBuildLandsOneCommitWithTheIntentTrailer` took 1.90-2.53 s and `TestTheReviewerApprovesUnchangedCodeWithoutRepairs` 2.17-2.55 s. Most of that is verification: a 0.5 s step sweep and about 0.66 s before `check_identity`, inside the pinned kogen-verification. That cost is outside this request. An absolute 2.00 s gate would therefore fail correct work for reasons this request does not touch. The contract states the requested 2 seconds as the extra time each silent-shell test may take over its plain landing counterpart. Today that extra is about 45 s.
- Addressed: "same coverage: a native shell call that writes nothing for longer than the loop's shell wait still yields; the command keeps running, its later output still reaches the Build, and the Build is not stopped as silent", together with "never weaken an assertion". Rule 2 keeps every assertion. The scenarios run each test against a copy of the pinned kogen-loop whose shell wait stops the command when it elapses (`stop`), and the test must fail there. The existing test catches that defect today too: in a scratch probe at HEAD, `TestSilentBuildShellNotStopped` failed after 45.69 s with `exit 70 err context canceled`, while `TestBuildLandsOneCommitWithTheIntentTrailer` passed against the same copy.
- Addressed: "exercises the real behaviour, not a copy of the decision logic". The tests run the real Build and review paths, and the real loop `tools.Tools` yield and retrieval (rules 1 and 2). The `stop` mutation proves that the loop's own wait is what the tests exercise.
- Addressed: "stays correct if the loop's wait changes". The scenarios run each test against a copy of the loop with waits of 90 s and 60 s (`waits`), and the test must pass. A clock that assumed 45 s, or a real sleep timed against 45 s, fails there.
- Addressed: "No new Kogen CLI command or flag, and no raised timeouts" and "a test-only time seam is not a user knob ... never a CLI flag, config key or environment variable". The seam is an unexported field (rules 1 and 4).
- Addressed: "If the wait lives in kogen-loop, use the smallest Go-level seam in the loop, which only Kogen's tests set". The loop seam already exists (`tools.Tools.ShellAfter`). kogen-build adds only the one unexported field that reaches it (rule 1).
- Superseded: "re-pins Kogen's kogen-loop dependency to b099dfa (cli/go.mod, go.sum and cli/loop-pin.json)" and "Re-pin to kogen-loop fe2bcd7". This module (kogen-build) has go.mod and go.sum at its root and no `loop-pin.json`. f2546ab already pins kogen-loop 7e80986, a later main whose sources contain `.kogen/intents/l-shell-wait-seam/` and `l-shell-wait-seam-rest/` and the `ShellAfter` field. go.mod and go.sum stay unchanged (rule 4).
- Addressed: the request's path `cli/build/silent_shell_test.go` (Kogen's layout) is this module's `build/silent_shell_test.go`; its `silentCommand = "sleep 47; printf 'done\n'"` is the line removed (rule 2).
- Omitted: the request's measured Kogen figures (TestSilentBuildShellNotStopped 60.5 s, TestSilentReviewShellNotStopped 55.7 s, the loop suite's 29 s). They are context; nothing asserts them.

## Tests
- A silent builder shell call yields on controlled time; its later output reaches the Build, which lands without being stopped: update `TestSilentBuildShellNotStopped` (integration)
- A silent reviewer shell call yields on controlled time; its later output reaches the review, which approves and lands: update `TestSilentReviewShellNotStopped` (integration)
- Each silent-shell test takes less than 2 s longer than its plain landing counterpart, still fails when the loop stops a silent command at its wait, and still passes with the loop's waits at 90 s and 60 s: acceptance scenarios running the real `go test` against the pinned and mutated kogen-loop (scenario)
- kogen-build relies on `tools.Tools.ShellAfter` yielding a running command whose later output a retrieval returns: new consumes test in `consumes/kogen-loop` plus its Inventory row (integration)
- With the seam nil, the builder's and reviewer's tools behave exactly as before, and the CLI gains no flag, key or environment variable: the existing `build`, `cmd/kogen-build`, contract and consumes tests pass unchanged (existing)
