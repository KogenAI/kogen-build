# Cover standalone reconstruction modes by command

Slug: standalone-reconstruction-json-contract
Model: not applicable — the change only adds command-level tests of existing behavior; it adds no state or interacting rules
Acceptance:
- .kogen/intents/standalone-reconstruction-json-contract/acceptance.feature
- features/steps/standalone-reconstruction-json-contract__steps.js

The `reconstruct` and `reconstruction` modes of the `kogen-build` command are documented to print one JSON envelope on stdout and to exit with the envelope's `exit_code`. Today `cmd/kogen-build/main_test.go` tests only argument parsing and two usage refusals, and never starts either mode as a subprocess. This Intent adds command-level tests to `cmd/kogen-build/main_test.go` that build the command, run it as a subprocess against a real temporary Git checkout, and check its process exit status, its stdout JSON and its writes. The tests cover three cases: a readback of an item with no recorded reconstruction; a `reconstruct` run that stops after the preserved phase; and a `reconstruct` run with an invalid `--stop-after` value. Out of scope: any change to reconstruction behavior, to `cmd/kogen-build/main.go`, to the `build` package or to the JSON schema. Nothing is removed or replaced. The acceptance checks the tests themselves: the package tests must pass on the unmodified tree and must fail when `main.go` is deliberately broken in one way each, covering a wrong exit status, a wrong envelope, a wrong dispatch and a write before refusal.

## Decisions
- The change is confined to `cmd/kogen-build/main_test.go`; no production file, README or golden file changes. (constraint: do not edit cmd/kogen-build/main.go or the build package) (evidence: cmd/kogen-build/main.go; cmd/kogen-build/main_test.go; README.md) (source: request)
- The new tests start the built `kogen-build` binary as a subprocess, as `TestStandaloneUsageRefusals` already does, and judge the process exit status and the stdout JSON decoded as the `result` envelope, not the library functions. (constraint: each case checks that the process exit status equals the envelope's exit_code and that stdout is valid JSON) (evidence: cmd/kogen-build/main_test.go; cmd/kogen-build/main.go; build/reconstruct_test.go) (source: request)
- Readback of an item with no recorded reconstruction: the process exits 1, stdout is valid JSON with `reconstruction.state` absent, and there are no checkout writes. The absent readback has only `state`, `attempts` and `wakes`, with empty `attempts` and `wakes`, and a non-null `error`. (constraint: no checkout writes, so the checkout outside .git is byte-for-byte unchanged, including no new directory) (evidence: README.md; build/reconstruct.go; build/reconstruct_test.go) (source: request)
- Reconstruct with a fixture that reaches the preserved stop (`--stop-after preserved`): the process exits 1, stdout is valid JSON with `reconstruction.state` interrupted and a non-null `error`, and there is no attempt or wake, so `attempts` and `wakes` are empty arrays. The archive holds its manifest. (constraint: no attempt or wake) (evidence: README.md; build/reconstruct.go; build/reconstruct_test.go) (source: request)
- Reconstruct with an invalid stop-after value: the process exits 2, the JSON `error` has category `usage` and kind `invalid_arguments`, and its message names the rejected `--stop-after` flag and the rejected value. There is no `reconstruction` object, and no archive or checkout writes: the archive path does not exist afterwards and the checkout outside .git is unchanged. (constraint: no archive or checkout writes) (evidence: cmd/kogen-build/main.go; README.md) (source: request)
- The fixture follows the documented evidence format for Problem20: a one-commit Git checkout, two retained receipt files whose SHA-256 is declared, and no live owners, effects, claims or unrevoked custody. It is built inside the test, mirroring the `build` package's own fixture. The test measures checkout writes by a content snapshot of the checkout excluding `.git`. (evidence: README.md; build/reconstruct_test.go; build/reconstruct.go) (assumption: the snapshot excludes .git because Git may refresh its own metadata there, and the requested no-write guarantee concerns the checkout's own files) (source: request)

It runs `go test ./cmd/kogen-build` on the unmodified tree, which must pass, and again with a copy of `main.go` substituted through a Go build overlay. The overlay travels in `GOFLAGS`, so the tests' own `go build` of the command inherits it. The step then requires a failing test assertion. Six mutations are used, one per property; the invalid stop-after value is chosen by the Build and is not fixed by the acceptance. ## Source comparison
- Request acceptance 1 (absent readback: exit 1, valid JSON, state absent, no checkout writes) is addressed by D3 and the scenarios "Readback of an unrecorded item must exit 1" and "Readback of an unrecorded item must not write into the checkout".
- Request acceptance 2 (preserved stop: exit 1, state interrupted, no attempt or wake) is addressed by D4 and the scenarios "An interrupted reconstruct run must report state interrupted" and "An interrupted reconstruct run must stop before any attempt or wake".
- Request acceptance 3 (invalid stop-after: exit 2, usage error naming the flag, no archive or checkout writes) is addressed by D5 and the scenarios "An invalid stop-after must be refused with usage exit 2" and "An invalid stop-after must not create files before refusing".
- The request's out-of-scope items (changing reconstruction behavior or the JSON schema) are honored by D1; the README's documented behavior is the contract and is unchanged.

## Tests
- Readback of an unrecorded item exits 1 with state absent and writes nothing: a subprocess test in cmd/kogen-build/main_test.go that runs `reconstruction --item` against a fixture checkout (scenario)
- A reconstruct run stopped after the preserved phase exits 1 with state interrupted and no attempt or wake: a subprocess test in cmd/kogen-build/main_test.go that runs `reconstruct --stop-after preserved` (scenario)
- An invalid stop-after value exits 2 with a usage error naming the flag and creates no archive or checkout file: a subprocess test in cmd/kogen-build/main_test.go (scenario)
- The new tests detect a wrong exit status, wrong envelope, wrong dispatch and early writes: the six main.go mutation scenarios of acceptance.feature (scenario)
