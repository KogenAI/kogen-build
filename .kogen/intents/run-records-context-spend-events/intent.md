Implement KOGEN-058, Studio kogen issue 17ee46f8-59fb-47d8-af56-8d48ea9891c0: native Build run records must expose where context is spent and retain enough content and identities to reconstruct the conversation. Replace metadata-only retention for native Build request items and native tool arguments/results with hash-linked content, deduplicated within each run. Add size attribution to native Build window resets and context-budget refusals. Preserve redaction, credential exclusions, current context ceilings/reserves, useful existing tests, and full final repository checks. This is the Build-owned slice in kogen-build, not an executor or review component change. Do not change go.mod or .kogen/project.yaml; do not add live accounts or external services to acceptance.

The following is the persisted interface to implement:

- Store blob content under `.kogen/local/runs/<run-id>/blobs/<sha256>`. Use lowercase SHA-256 over the stored bytes. A string is its exact UTF-8 bytes; other item values are canonical JSON using the existing encoding convention. A blob has no added newline. Keep the blob directory private (0700) and blob files private (0600), like the working-context archives. Identical content referenced again, including across requests and tools, resolves to one file in that run. Persist blob failures through the existing run-record error/checkpoint mechanism, not successful dangling references. This does not require changing checkpoint schema or retroactively populating older run folders. Existing run/checkpoint ownership and digest conventions are evidenced by build/core_run.go, build/context.go and build/records.go. (evidence: build/core_run.go; build/context.go; build/records.go)
- Each native Build `request` event retains its existing fields and gains `items`, an ordered array of `{sha256, bytes}` references for the actual input sent after any local reset/prefill. References preserve repetitions and input order even though storage deduplicates. This is model-facing item content, not HTTP headers or credentials. The existing Request boundary and event location are in build/build.go. (evidence: build/build.go)
- The same native Build request record gains `response_id` from the provider response identity and `response_items`, ordered blob references to its response items. Keep provider response item IDs and call IDs inside these items, together with names and arguments. Retain `operation_id` and existing usage fields. Missing provider identity stays empty rather than inventing one. A combined request/response event is sufficient; no separate response event or new reconstruction command is required. The current event already correlates a completed response and its request. (evidence: build/build.go)
- Native Build `tool_call.arguments` and `.result` retain the existing `{sha256, bytes}` reference shape but now resolve to content in the same blob store. Keep `call_id`, tool name, cut-result fields and source measurements. Store the actual delivered tool result, including already-applied cuts/refusals, rather than rereading source files to reconstruct a result. Terminal finish also has a stored result. Do not re-expand excluded content or record transport headers, authentication configuration, or credentials. Do not change `review_tool_call`. The native tool event and delivered result boundary are in build/executor_native.go; source measurements remain in build/records.go. (evidence: build/executor_native.go; build/records.go)
- Native Build `window_reset` events gain `breakdown` with integer `before_bytes`, `after_bytes`, `summary_bytes`, and maps `mandatory_bytes_by_kind`, `optional_bytes_by_kind`. Emit a native Build `context_budget_exceeded` event with owner and the same breakdown when context reduction cannot fit; preserve the existing structured refusal and no-archive/no-commit behavior. Before/after are the complete rendered request byte measurements before and after attempted reduction, not token estimates. Summary bytes are the UTF-8 content bytes of the generated reset message. Mandatory attribution covers the carried opening and reset messages; optional attribution covers the remaining attempted carried items. Group canonical item JSON byte lengths by `type`, falling back to `role`, then `unknown`. Empty maps are objects. These item-attribution maps deliberately exclude transport overhead, policy and tool-definition serialization; they are not falsely presented as summing to the complete rendered request bytes. On refusal, after/summary/maps describe the rejected candidate reduction. Keep existing fields for compatibility, including legacy fields named `input_tokens_before/after`; do not modify actual measurement, reset policy or reserves. The reduction and measurement points already exist in build/context.go. (evidence: build/context.go)

Add or update focused implementation tests for these rules and update event goldens only for deliberate changes. Retain all useful existing tests. README documents `go test ./... -update` for deliberate golden regeneration and requires reviewing the diff; frozen unrelated goldens are not permission to rewrite unrelated behavior. Final checks remain `go build ./... && go vet ./... && go test -race -count=1 ./...`, plus the configured format/compile/vet/go-test and this acceptance. Do not move broad suites inside acceptance steps. (evidence: README.md; .kogen/project.yaml)

The acceptance driver overlays its submitted build-tagged Go fixture into the real build package and runs only that fixture's named test per assertion. It reuses the existing local fake provider/project setup and invokes the real native Build entry point, plus exact local reset attribution checks. It does not require Build to invent a test name or edit a protected test. The helper is excluded from ordinary package discovery unless explicitly enabled. Existing local fixture and reference measurement facilities are in build/helper_test.go and build/context_test.go. (evidence: build/helper_test.go; build/context_test.go)
